О генераторе:
отправляет логи батчами т.е сразу
На сайтах логи часто прилетают на сервер анализа именно пачками (батчами), где данные за минуту уже посчитаны на стороне клиента. Это экономит ресурсы сети. Так что генератор имитирует взрослую, оптимизированную систему.

Отправлено:
`    {
    'user': 'user_1',
    'event': 'file_download',
    'ip': '192.168.1.152',
    'request_count_1m': 10,
    'download_size_mb': 2.46
    }`

надо делать:

- Нету авто бана(надо делать временным )
- Додумать еще

на бэкенде есть:
1.есть черный лист - защита по ip

2.есть защита от брутфорс - много ношибок авторизации(нету авто бана):
` 
if log.event == "login_failed" and log.request_count_1m > 3:
        brute_force_penalty = min((log.request_count_1m - 3) * 5, 50)
        base_risk += brute_force_penalty
        explanations["brute_force_detection"] = (
            f"Обнаружены признаки брутфорса. Зафиксировано {log.request_count_1m} "
            f"неудачных попыток авторизации за минуту от IP {log.ip}."`

3.есть динамичные правила из бд с риском

4.Гибридный скоринг (Static Rules + AI): оценивается каждый лог по шкале риска от 10% до 100%. Мы не полагаемся на что-то одно: базовый риск формируется строгими правилами, а аномалии доверяются ИИ.

5.Асинхронная обработка (FastAPI Background Tasks): Сервер работает молниеносно. Запись сырых логов и отправка критических инцидентов в Supabase происходят в фоновом потоке. Клиент (или генератор) получает ответ мгновенно, бэкенд не блокирует сеть.

6.Адаптивное переобучение «на лету» (/api/v1/retrain): Модель можно переобучить прямо во время работы системы без перезапуска сервера. При этом кэш правил безопасности и черных списков принудительно синхронизируется с базой данных Supabase.

7. Мы используем 4D-вектор признаков для анализа каждой пачки логов:
   Интенсивность (request_count_1m)
   Объем трафика (download_size_mb)
   Тип события (кодированный event_type)
   Текущий час суток (current_hour)

8.Наш бэкенд не просто говорит «тут опасно», он детально обосновывает свое решение для администратора безопасности. В таблицу security_alerts улетает полный разбор инцидента:
Если сработал ИИ, генерируется понятный отчет: «Интенсивность от IP X составила 69 запр/мин, а объем 210.59 МБ, что нетипично для времени суток 2:00».
Если IP в блеклисте, подтягивается конкретная причина: «Причина: подозрительная активность».
Если сработало комбо (ИИ + Блеклист), риски суммируются до максимальных 100%, собирая все объяснения в один объект.
